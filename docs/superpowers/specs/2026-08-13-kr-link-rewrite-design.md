# 글로벌이 글로벌을 링크하면, 한국은 한국을 링크한다

맨틀 글로벌 글은 자기 다른 글을 자주 링크합니다. `x:2087188550144180274`의 두 번째 트윗이 그렇습니다.

```
Start trading: https://fluxion.network/trade
https://x.com/Mantle_Official/status/2087156149368082696
```

번역은 이 링크를 그대로 옮깁니다 — 스타일 가이드가 그러라고 했고(`translation/style-guide.md:287` "링크: URL 그대로 유지"), 원문에 글로벌 링크가 있는 4건 전부 한글에도 살아 있습니다. 규칙대로 동작하고 있습니다.

문제는 **한국 독자를 영어 원문으로 보낸다**는 것입니다. 링크된 그 글에도 한국 글이 있으면, 그쪽을 가리켜야 합니다.

```
https://x.com/Mantle_Official/status/2087156149368082696
                    ↓
https://x.com/0xMantleKR/status/2087418810458382585
```

## 얼마나 흔한가

프로덕션 `x_threads` 실측입니다.

| | |
|---|---|
| 활성 스레드 | 230개 |
| 그중 글로벌 자기 글을 링크한 것 | **21개 (9%)** |
| 링크 대상 | 30건, 그중 26건은 이미 수집돼 있음 |
| 번역 플로어(2026-07-27) 이후로 좁히면 | 4개, 대상 4건 전부 수집돼 있음 |
| 원글과 링크 대상의 시차 | 0.1일 · 0.1일 · 20일 · 28일 |

시차가 이 설계를 가릅니다. **0.1일**은 "ICYMI, 아까 그 글" 패턴이라 대상도 같은 시기에 파이프라인을 통과합니다. **20·28일**은 번역 플로어보다 오래된 글이라 **한국판이 영영 생기지 않습니다.**

## 범위: x 타입만

`x` 타입은 원문에 가까운 번역이라 인라인 링크를 그대로 나릅니다. 나머지(`announcement`·`kakao_notice`·`explainer`·`casual`·`kol`·`pr`)는 재작성이고, 끝에 한국 X 게시물을 가리키는 CTA가 붙습니다 — 독자는 어차피 한국 글로 갑니다.

**관측이 아니라 판단입니다.** 프로덕션에서 변환까지 끝난 아이템 2개는 둘 다 원문에 글로벌 링크가 없어 표본이 0입니다. 재작성이 인라인 링크를 요약해 없앤다는 것은 합리적 추정이며, 반례가 나오면 그때 범위를 넓힙니다.

## 맨틀 글로벌 링크만

`isSweptAccount`(`src/domain/sweptAccount.ts:42`)로 핸들을 판별합니다. @xStocksFi·@InsightXHQ·@MerchantMoe_xyz 같은 다른 계정 링크는 **건드리지 않습니다** — 한국판이라는 게 존재하지 않습니다. 실측에서 그런 링크가 글로벌 자기 링크만큼 나옵니다.

## 언제: 발송·미리보기 시점

어제 X 링크 CTA와 같은 자리, 같은 부품입니다.

```
링크 URL → parsePostUrl (src/domain/publish/xReconcile.ts:183) → { handle, rootId }
        → isSweptAccount(handle) 아니면 통과
        → 아이템 `x:<rootId>`
        → resolveXPostUrl(그 아이템의 translation, 그 아이템의 deliveries)
        → 있으면 치환, 없으면 원문 그대로
```

`resolveXPostUrl`(`src/domain/formatting/xLinkCta.ts`)은 이미 있습니다. 새 해석기는 필요 없고, 텍스트에서 링크를 찾아 바꾸는 순수 함수 하나만 추가됩니다.

붙이는 지점도 동일합니다 — `SendChannels`의 `emit` 직전, `/emissions`의 `emitAll` 직전. **emit 앞**이어야 하는 이유도 같습니다: 길이 초과 판정이 치환된 길이를 세야 합니다. 한국 URL이 글로벌보다 짧을 수도 길 수도 있습니다.

한 텍스트에 링크가 여럿일 수 있으니 전부 훑고, 각각 독립적으로 판정합니다.

## 저장된 번역문은 고치지 않는다

`translations.korean_text`에는 원문 링크가 그대로 남습니다. 그게 원문의 충실한 기록이고, 스타일 가이드가 요구하는 바입니다. 치환은 내보내는 순간에만 일어납니다.

부수 효과 하나: 검수 편집기에 보이는 글과 [복사]가 주는 글이 링크에서 달라집니다. CTA도 이미 같은 성질을 갖고 있으므로 새로운 종류의 어긋남은 아닙니다.

## 한국판이 없을 때는 막지 않는다

글로벌 링크를 그대로 두고 2차 검수에 알립니다.

CTA 게이트(`xUrlBlock`)와 **다르게 차단하지 않습니다.** 차단이 맞으려면 기다리면 풀린다는 전제가 있어야 하는데, 번역 플로어보다 오래된 대상은 한국판이 영영 안 생깁니다. 차단하면 영구 차단입니다.

알림 문구는 "바꾸세요"가 아니라 상태와 선택지를 말합니다:

```
링크된 글로벌 글 1건은 아직 한국 글이 없습니다. 먼저 올리면 자동으로 한국 링크가 됩니다.
```

한국판이 **있을 때는 아무 말도 하지 않습니다.** 미리보기가 이미 한국 링크를 보여주고 있으니 알릴 것이 없습니다.

## 안 하는 것

- **게시 후 소급 교체.** X는 게시 후 API 수정이 안 됩니다. 텔레그램은 `deliveries.post_id`에 message_id가 남아 기술적으로 가능하지만, 텔레그램은 이 작업의 범위 밖입니다. 범위가 X 하나면 교체 수단 자체가 없습니다.

  그리고 대부분 저절로 안 생깁니다: A가 B를 링크하면 B가 더 오래된 글이고 파이프라인은 시간순이라, B의 한국 글이 먼저 나갑니다. 문제는 B를 건너뛰거나 검수에서 오래 붙들 때만 생기고, 그건 검수 알림이 다루는 경우입니다.

- **다른 타입으로 확대.** 위 "범위" 참조.
- **저장된 번역문·변환문 수정.**
- **다른 계정 링크 처리.**
